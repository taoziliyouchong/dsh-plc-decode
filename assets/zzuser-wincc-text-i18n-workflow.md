# zzuser-wincc-text-i18n-workflow —— 西门子触摸屏项目文本翻译

`Screens.xls / Others.xls / Messages.xls` 是 WinCC flexible（SMART）把工程文字按「画面 / 其它 / 报警」三处导出成的 Excel。英文列多半是半成品：有的空着，有的还是中文，更多是**串位**——这类表不能当成"填空"，得当校对。

## 一、格式契约（动之前先认清这四条）

- 第 1 行 `$_Languages`，第 2 行是语言名（第 1 列＝源语言，第 2 列＝目标语言），第 3 行 `$_Typ(...)`，再几行 `//` 注释。
- **第 1 列是匹配键**：导入时按它回工程里找对应文本。改一个字，那一行就对不上、白改。所以只改第 2 列。
- 文本通常被 `<text>…</text>` 包着；**换行是真换行**（Excel 单元格里 Alt+Enter 那种），不是字面 `\n`。映射文件里用 `\n` 表示，脚本读入时还原。
- 目标列出现 `$_ignore`：这句源文本在工程里已经有多个不同译文，导出时被替换掉了。**它不是"不用翻"，照样译、照样填进目标列**（空文本 `<text />`、纯符号/缩写除外）。导入时软件若仍按多译文冲突跳过，那几处屏上才不会变，这时才需要进工程手动统一。留着 `$_ignore` 交给用户＝表里还是中文，等于没翻。

## 二、四步

1. `scan`：出「待译清单.tsv」＋「分型报告.md」。
2. 逐条出译文，写成 `map.tsv`（一列中文原文、一列英文，制表符分隔）。
3. `apply`：回写目标列，出**同扩展名**.xls。
4. `check`：键列没动、没有未译、没有残留 `$_ignore`、没有串位（源无中文而译文更长）、没有一源多译。

工具：`zzuser-wincc-text-i18n`，`action=scan | apply | check`。

## 三、分型只解决一半

scan 判得出来的是：空译、中文残留、`$_ignore`、非中文同形（编号／日期格式）、**编号行挂词**——源文本不含中文（纯编号／代号）而译文更长的行，例如 `Q10` 对 `Q10 top box`、`Q23` 对 `Q3 Reject`。这一类就是串位：别行的功能词落到这一行了，按「源只有编号，译文也只留编号」处理；日期格式串（`yyyy-M-d H:mm:ss`）两列本来就不一样，不算。

判不出来的仍是错译：中文对得上、译文却是另一个意思的那种，必须逐行看一遍。错译常见的三种样子：

- 同类多行共用一句：`Q80~Q87` 全写 `Q15 Jet Glue 1`，`I80~I87` 全写 `I20`。
- 上一行的话落到下一行：`Q20~Q27` 写着 `Q0 / Q1 / Q2 / Q3 Reject…`，那是 Q3~Q7 的。
- 明显张冠李戴：`拓宇LOOG` → `Air pressure alarm Off`，`返回` → `Adjustment Screen`，`中性` → `Air pressure alarm On`。

## 四、几条判据

- **字典优先于模型译法**：用户给了字典文件（中文→英文的对照表）时，字典里有的条目逐字照用——不为词形统一而改写、不为屏宽而压缩、不换同义词；只有字典里没有的条目才自行翻译。字典里没有的条目，外语撑不住控件时按控件宽度切成多行（见入口技能「外语撑破控件就分段」）。字典自身可能一词多形（`Bag Opening Servo` 与 `Bag Open Servo Not Reset` 并存），按条目各照原样，不做全局统一。写回 XML 文本节点时 `&`/`<`/`>` 用实体（`&amp;` 等），导入后还原成原字符。
- **以中文为准**。英文顺不顺口是次要的，和中文对得上才要紧。
- 用户给的字典文件可能一表多语且列位错开（实测 `HMI information .xls`：中文在 A、英文在 B、越南语前半段在 G、报警段错到 K），取某语种时两列都要读，别只看一列就下"字典没有"的结论。
- **一源一译**：同一句中文，全表只能有一个英文。同一文本两种译法，导回工程就产生多译文，下次再导出又变成 `$_ignore`，越改越乱。
- **I/O 点位中文只写编号的，英文也只写编号**。别拿英文列里的话反推功能——那多半是别行串过来的。中文写了功能的（`Q5剔废`），才补功能。
- 历史用词能用就不动（`Coder` 不改 `Encoder`），免得现场对不上。
- 型号、电话、日期格式、公司名：原样，不翻译。
- 地址这类改过的信息，以中文那一条为准重译，英文里常留着旧厂址。

## 六、出表细节

- **产物写回源文件同路径、同名覆盖**，不要新建「翻译_项目文本」之类的目录另存——用户按原路径找文件，挪走或改名他就找不到。覆盖前先备份原件（项目侧放工作区 `_过程产物\`，不在源目录堆 `.bak`）。附加件（对照表等）放 `_过程产物`，不污染源目录。
- **只改目标单元格，别整表重写**：`xlwt` 重建整表会吞行（实测 394 行写完剩 393，之后整表错位），也会丢掉别的列。`apply` 默认走 Excel COM：复制源表 → 只改变化的格子（PowerShell 调 `Excel.Application`，不需要 pywin32）→ `Save`，行数、列数、格式、其他列全原样；没有 Excel 才退到 xlwt，且写完回读核对行数与键列，对不上直接报错。
- 必须出 **.xls**：软件的导入对话框按扩展名过滤，给 .xlsx 会选不到。
- 新版导出表会带第 3 列元件路径（`\设备_1\HmiScreenFolder\…`），能定位这句文字在哪个画面——别丢。
- 写 `.xls` 首选 Excel COM（`apply` 内置，Windows 有 Excel 就能用），无 Excel 时用 `xlwt`（`<python> -m pip install xlwt`）；读 .xls 借 LibreOffice Kit 转 xlsx。LibreOffice Kit 只能 xls→xlsx，不能 xlsx→xls，别拿它当写 .xls 的退路。
- 空列照写：原表有几列，产物就几列。

## 七、交付前必须交代的一件事：导入≠保存

项目文本导入只改内存里的工程，**不保存工程就等于没导**——关掉重开就回到上次保存的版本，屏上还是中文。判断有没有真写进去，看同目录 `.hmismart` 的修改时间：导入并保存后会变成刚才的时间，不变就是没保存。

**复核要拿工程重新导出的表来核，不能核自己手里那份。** 自己的表里全对，只说明表对；工程里对没对，要让它自己导一份出来比。工程重新导出时，第 5 行的导出时间注释会变（`//$_导出…`），比对键列时把这类注释行排除。

所以交付话术里固定三步：导入 → **保存工程** → 点「刷新」复核。
另外两个会让人误判的点：

- 项目文本列表打开后不自动刷新，导入完要手动点「刷新」才看到新值。
- 工程里存在多译文冲突时，导出表会多出一行 `//至少一个文本存在多种不同的翻译…`。等这些条目被统一后，这行注释会消失、表少一行——这不是格式坏了，是冲突清掉了。

## 八、导入与导出按文本类型分开，一次一类

Screens（画面）、Others（其它）、Messages（报警）是**三个独立文件**：导出时按类型各出一个文件，导入时一次只吃一个文件（软件按文件里的 `$_Typ` 判断类别）。所以：

- 导回一个工程要**分别导三次**（Screens.xls、Others.xls、Messages.xls），只导一个文件，另外两类的屏上文字仍是原文。
- 导出同理：切换文本类型分别导，或导出后确认目录里三个文件都在。
- 导出日志（输出窗口）会逐类打印 `导出: 画面 / 导出: Others`，可以据此核对有没有漏类。
