# NB 系列触摸屏文本库翻译（.nbp / .whe）

`拓宇`这类用 NB 软件做的屏，工程是 `.nbp`（主工程 XML）＋ `HMI0\HMI0.whe`（画面 XML），
文本库另导出成 `TextLib.csv`。三个文件都是纯文本，可直接解析，不需要开软件。

## 一、认格式

- `.nbp`：`<NBProject DBVersion="...">`，画面内容不在这里，只存工程设置与 PLC 配置。
- `.whe`：`<HMI>` → `<Frames>` → `<Window ProjectID Name>` → `<Parts>` → `<Part Type=...>` → `<Lable>`。
  22 个画面，系统画面名是英文（Login Window、HEX/ASCII/NUM Keyboard、Confirm Action Window 等）。
- `TextLib.csv`：UTF-16LE + BOM，**LF** 换行，四列制表符＋双引号，条目之间空行。
  结构是每组：`"Name:"\t"条目名"` / `"Status:"\t"状态数"` / `"Language"\t"Language1"\t"Language2"\t"Language3"` / 若干数据行。
- 数据行里的 `$_return_$$_enter_$` 是软件内的换行控制符（不是字面量），原版英文靠它分行。

## 二、走库怎么判（最容易判错的一处）

元件文字全在 `<Lable>` 里，两个属性决定：

- `UseTextLibrary="Yes"` / `"No"`
- `LibraryTextName="条目名"`（对应 CSV 的 `"Name:"`，不是中文列）

**勾了库 ≠ 走库**：必须再核 `LibraryTextName` 是否真的在库条目名里。条目不存在时，软件回退显示
`<Font>` 里内嵌的字，屏上看着正常、切换语种却不变——和没走库一个效果，肉眼看不出来。

判定顺序：

1. `UseTextLibrary=Yes` 且库里有该条目 → 正常走库，跳过。
2. `UseTextLibrary=Yes` 但库里查无此条目 → **假走库**，当作翻不到处理。
3. `UseTextLibrary=No` → 未走库。文字在 `<Font>文字</Font>`；多状态元件每个 `<State>` 一组。

## 三、扫什么

- 遍历**所有** `<Lable>`：静态标签、按钮、开关、指示灯的文字都在这，别只扫一种元件。
- 系统画面（画面名是英文的那批）不管。
- IO 地址标注（纯编号如 `100.03`、`0.9`）不管。
- 报警单独看，见第六节。

## 四、翻译口径

- 字典优先：中文命中字典的逐字照用，不改写、不压缩、不换同义词。
- 字典没有的：英文保留原版英文（不是我造的），第三语种留空，绝不自行翻译。
- 字典备注列写「请删除」的条目：不翻、保持原样，也不进缺译表。
- 原文本身是英文（中文列不含汉字）的条目：三语填同一个值。
- 纯英文且没勾库的控件文字：不管。
- 原版英文含 `$_return_$$_enter_$` 时：译文单行显示宽度超过原版最长行才按原行数在空格处切分
  （全角字符按 2 计宽），不改变文字内容。

## 五、缺译清单

- 固定三列：中文 / 英文 / 韩语，没有的留空；按中文去重（一源一译）。
- 内容 = 库内缺译（英文空或第三语种空）+ 翻不到的控件文字（未勾库的 + 假走库的）。
- 已在库内缺译里出现的中文不重复列。

## 六、报警

- `.nbp` 里 `<AlarmObjects>` / `<EventObjects>` / `<Event>` 都是空节点 = 没有自定义报警/事件配置。
- 屏上的报警通常是 Word Lamp 读某个文本库条目的状态字（状态显示类）。要核条目 `Status` 是否
  覆盖元件 `StateCount`，不够时多出来的状态会显示空白。

## 七、切了语种显示不出目标语言（韩文/日文/俄文）

文字有没有、走不走库都正常，但切过去画面上不出字——按下面四处依次断，四处都通才显示：

1. **语种槽有没有字**：`.nbp` 的 `<TextObjects>/<LableText>/<States>/<State>` 下 `<Text>` 的个数＝语种数，
   第 N 个就是语种 N。某语种槽空＝切过去空白。
2. **字体有没有该语种的字形**（最常见的一处）：
   - 语种默认字体在 `.nbp` 的 `<DefaultLangFontInfo>`，几条 `<VectorFont>` 就是几个语种；
   - 元件标签的三语字体在 `.whe` 的 `<Lable>/<Text>/<VectorFontList>`，三个 `<VectorFont>` 按语种顺序；
   - 这两处字体名一样、且该字体不含目标语种字形，就画不出来（软件用方格或空白顶上）。
   - 软件自带向量字体清单在 `<安装目录>\vectorfonts.xml`，按语种给默认字体：
     **DFHEI5＝简体中文（20976 汉字、0 谚文）**、DFNB-TW＝繁体、DFNB-EN＝西文、
     **DFNB-KR＝韩文（2350 个韩文音节）**、DFNB-JP / DFGNB-JP / DFPNB-JP＝日文。
   - 核对办法：读 ttf 的 cmap 数 U+AC00–U+D7A3 有没有字形，比看字体名可靠。
3. **下载包里带没带**：编译输出 `tar\HMI0\font_*.ttf` 是按工程实际用到的字裁出来的子集。
   里面没有目标语种字形，屏上一样不显示——改完字体必须重新编译下载。
4. **切语种入口**：运行时靠 LW9130 切语种（`LW9130＝语种序号−1`，0 起）；切语种的画面上要有对应按钮，
   否则屏上没法切过去。

改字体：

- 入口：【HMI 属性】→【触摸屏扩展属性】→【语种设置】（文本库窗口里也能进）→ 当前编辑语种 →
  字体类型选矢量字体 → 字体属性里选该语种字体。
- 【语种设置】**不会**改已有元件标签的字体。两种刷新法：
  ① 逐个元件把【标签】页「使用文本库」取消勾选再勾上；
  ② 把工程当前编辑语种切到该语种，全选元件，用字体工具栏统一设字体（工具栏改的是当前状态、当前语种）。
- 韩文字形 2350 个，改完屏端字体体积会明显变大，下载前留意屏的存储余量。

## 八、改文件

- 只改数据行第 3、4 列（英文、第三语种），中文列与全部结构行原样；写回 UTF-16LE+BOM、LF。
- 改前备份原件（`E:\chajian\_backup\<日期>-<主题>\` 保留原相对路径）。
- 目标 xlsx 正被 Excel 打开时：用 COM 连活动实例（`Get-ActiveObject`），**先查 `Saved=True`** 再改；
  有未保存改动就不动，问用户。改完 `Workbook.Save()`，不要 `Quit`。
